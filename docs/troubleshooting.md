# 故障排查

## 达到额度后没有切换

先确认当前窗口是通过 `claude-auto` 启动的；直接运行原版 `claude` 或 `claude-accounts use` 不会启用控制器。已经运行的窗口不会因为安装了新文件就自动变成新版控制器。

控制器只有收到可确认的官方额度错误才切换。它会等待进行中的工具、核实子代理终止状态、校验会话检查点，再退出旧客户端。保存不完整时会保留窗口并报告原因；不要强制杀进程来绕过校验。已失败子代理和经过验证的外部监视服务不应无限阻塞这一步。

检查 `claude-accounts status`。未登录、重复登录同一个身份、停用或仍处于已知限额窗口的账号不会被选中。没有下一账号时，退出码为 `75`，输出包含原 session ID 和恢复命令。

## 切换一次需要几分钟

长会话的临时文件可能包含数 GB 图片、视频和工具输出。早期版本会在退出前、退出后重复复制全部文件，再多次全量读取校验；已有备份虽然按内容去重，临时复制和落盘仍会消耗大量 I/O。多个窗口同时切换会进一步争抢磁盘。

从启动器 `2026-10-10.1` 起，已存在的对象先核对内容，不重复写入；同一进程内，文件身份、设备、类型、大小、mtime 和 ctime 均未变化的已验证对象可以复用。退出时新增的历史仍会保存，文件改变或备份损坏会使缓存失效。缓存不会跨进程持久化，因此首次保存、重新启动后的首次验证，以及新增的大文件仍需要时间。

保存期间终端会显示文件数、复用数和新增写入量。每个运行目录的 `rotation-timings.jsonl` 记录切换阶段，检查点的 `checkpoint_stats` 记录归档耗时和复用量；这些属于私有诊断数据。更新磁盘上的脚本不会替换运行中控制器的 Python 代码，须在工作允许时正常退出后重新启动或恢复原会话，才能使用新逻辑。

## 反复提示“上下文恢复尚未通过校验”

恢复钩子必须确认原会话 ID、历史路径和会话所有权。旧版钩子还会在持有生命周期锁时扫描全部历史收据；长会话恢复后，如果文件身份改变导致扫描游标失效，可能超过原版 15 秒钩子时限，来不及保存校验结果，后续提示因此一直被拦住。

从 `2026-10-10.3` 起，钩子只处理本次事件与已记录状态；切号控制器在退出前读取缺失的历史收据，在锁外扫描，再检查是否有并发钩子更新，避免覆盖新记录。检查点完整性、原 ID 与路径不匹配时仍会阻止恢复，不能手动把 `verified` 改成 `true` 绕过检查。私有会话状态的 `compaction_window_env` 可核对最近一次原版钩子实际继承的窗口环境值；它不是模型总窗口或 `/context` 的完整解析结果。

## 压缩失败，正在自动重试

这是[压缩恢复插件](compaction.md)对失败摘要的有限重试。三次追加尝试用完仍失败时会明确报告；恢复成功会显示前后 token 数。主窗口等待后台代理时也可能显示子代理的压缩状态。提高窗口不会取消已经开始的摘要请求，`1/3` 等计数也不代表账号切换次数。

## 重置后没有优先使用该账号

在额度台刷新该账号，或查询它的重置卡。启动器需要近期、完整的官方 5 小时及 7 天额度样本，才能清除旧的负缓存；手动备注和过期倒计时不够。确认恢复后会在约五分钟内优先选择该账号。后发生的新额度错误仍然优先于旧查询结果，停用状态不会被自动清除。

显式 `claude-auto --account PROFILE` 会优先遵循你指定的可用账号。恢复优先级用于选择自动候选账号。

## Could not refresh your login…another Claude Code process

启动器会等待官方刷新锁，并针对这个确切错误安排最多两次续试（60 秒、120 秒）。输入内容、开始新任务、账号停用或恢复校验失败会取消续试。它不会删除官方锁。

如果反复出现，先有序退出不再使用的官方客户端窗口，再用 `claude-accounts login PROFILE` 重新完成官方授权。保留当前工作的会话 ID；更新版本后可先运行 `recovery SESSION_ID` 检查，再 `recover SESSION_ID` 继续。

## API 无响应、代理超时

网络错误不会触发跨账号重试。配置代理时，启动器默认设置 `API_TIMEOUT_MS=60000`；原版客户端仍可能根据自身策略重试，所以总等待时间不保证在一分钟以内结束。检查代理、DNS 与官方服务状态。需要其他超时时可显式设置环境变量，不必修改源码。

## 额度未知、重置时间已经过去

“未知”与“耗尽”不同。状态栏可能只给出部分窗口，`/usage` 也可能因登录状态、首次设置、网络或客户端格式变化而查询失败。旧数据会保留并显示来源与时间；点击刷新来取得新证据。首次采集逐个执行，多账号初始化可能需要一段时间。

## Artifact comment monitor didn't resume

这是原版 Claude Code 的临时监视能力恢复失败提示。保存聊天记录和子代理 ID 不等于能重建所有后台服务。按客户端提示重新发布 Artifact 以恢复评论监听；自建的长期脚本可以按[配置说明](configuration.md)交给独立用户服务承载。

## 重置卡显示待核对

如果兑换请求超时，服务端可能已经消耗了卡片。系统不会重发结果不明的请求。重新查询余额，并到官方用量页面核对结果；不要通过删除操作记录来强行重试。接口不可用或没有资格时，额度台会显示错误或未知状态，不把它解释成“没有卡”。

## 报告问题

提供操作系统、Python / Claude Code 版本、启动命令（去掉私有路径）和最小复现步骤即可。请勿上传注册表、凭据、原始事件日志、上下文备份或完整 `/api/status` 响应；这些数据可能含邮箱、会话内容和私人路径。用 `.test` 邮箱及虚构 ID 制作最小样本。
